제가 맡은 일

IoT를 맡아 키링·앱·서버 사이의 통신 조건을 정리했습니다. 기판에 맞춰 연결선을 직접 압착하고 케이스를 출력·조립했습니다. 실물 증상과 완료 기준을 제시했고 AI가 펌웨어 수정과 검사 코드를 도왔습니다. 앱과 서버는 팀과 연동했습니다.

  • BLE
  • Zephyr / C
  • USB 진단

판단하고 바꾼 과정

기판과 전선부터 확인

제작 기판의 2.0mm 소켓에 모듈의 2.54mm 핀이 그대로 맞지 않아 LED와 진동 모듈의 연결선을 직접 만들었습니다. 진동선 한쪽을 반대로 꽂은 것을 발견하고 전원을 분리한 뒤 핀 순서를 대조해 다시 연결했습니다.

초기화하면 원인이 사라지는 문제

전에 만난 상대와 다시 마주쳤을 때 출력이 없는 이유를 알아야 했습니다. 기록을 지우면 그 이유도 사라집니다. 건수만 보여 주던 USB 출력에서 특정 상대의 상태와 억제 사유까지 조회하도록 요청했습니다.

호스트 검사 뒤 보드에서 발견한 누락

호스트에서는 조회가 저장 상태를 바꾸지 않는지 검사했습니다. 실제 보드에서는 긴 결과의 일부 줄이 빠졌습니다. 로그 스레드가 앞줄을 처리한 뒤 다음 줄을 보내도록 수정하고, 첫 줄·마지막 줄·예상 행 수와 두 저장 영역의 전후 지문을 함께 대조했습니다.
