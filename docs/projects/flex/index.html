GPT API · 월별 소비 분석

월별 총액과 카테고리별 합계를 백엔드에서 GMS를 통해 GPT 모델로 보내고, 결과를 구조화된 JSON으로 저장하는 흐름을 점검했습니다. 소비가 없는 달에는 데이터 부족을 표시하고, 소비가 있는데 모델 호출이나 응답 해석이 실패하면 같은 집계로 규칙 기반 분석을 만들도록 했습니다.

Vue 3 · JavaScript

가입과 소비 기록 화면에서 입력한 값이 API의 필수 필드와 맞는지 확인했습니다. 서버를 복구한 뒤에도 화면이 기대하는 필드명과 실제 응답이 달랐습니다. AI의 도움으로 인증 상태, 라우터, API 호출을 맞추고 프런트엔드 빌드를 확인했습니다.

제가 맡은 일

초기 서비스는 팀원과 함께 기획했습니다. 저는 가입과 기록 화면에서 누락을 발견해 전체 흐름의 재검토를 요청하고 월별 분석의 입력·저장·예외 조건을 확인했습니다. 구현과 테스트 실행은 AI가 도왔습니다.

판단하고 바꾼 과정

가입 실패와 빈 목록을 분리

6월 14일 가입 오류와 카테고리가 비는 증상을 확인했습니다. 폼만 바꿔서는 필요한 데이터가 준비됐는지 알 수 없어 설계도와 계정·프로필·카테고리 모델을 함께 대조하도록 요청했습니다.

계정만 남는 실패 방지

프로필 생성이 실패해도 계정만 저장되면 사용자는 다시 가입하기 어렵습니다. 사용자와 프로필 생성을 한 트랜잭션에 묶고, API의 선행 이메일 검사와 DB의 유일성 제약을 각각 확인했습니다. 카테고리는 테이블을 만드는 단계와 기본 8개 항목을 넣는 단계를 나눴습니다.

빈 달과 외부 호출 실패

월별 분석에는 실제 소비 집계를 전달하고 결과를 구조화해 저장하도록 했습니다. 기록할 소비가 없는 달은 데이터 부족으로 표시하고, 기록은 있지만 외부 분석 호출이 실패했을 때는 규칙 기반 대체 결과를 사용하도록 점검했습니다.
