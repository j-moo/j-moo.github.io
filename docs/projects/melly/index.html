제가 맡은 일

7월 15일 로그인·팬미팅 목록 화면을 직접 설계했습니다. 프런트엔드를 맡아 실제 요청과 반복된 오류를 전달하고, 팀 백엔드 코드와 대조할 부분을 짚었습니다. AI의 도움으로 화면 분기와 회귀 테스트를 보완했습니다. 공식 기간은 7월 13일~8월 7일이며 통화 입장 수정은 이후 보완 작업입니다.

  • React
  • TypeScript

판단하고 바꾼 과정

사용자의 입장을 막은 두 번째 요청

입장 토큰은 영상 방에 접속할 권한을 담고 있고, 상태 조회는 타이머와 종료 표시 등에 쓰입니다. 두 요청을 하나의 성공 조건으로 묶자 상태 조회만 거절돼도 유효한 토큰을 받은 사용자가 영상 화면을 열 수 없었습니다.

실패한 요청에 맞춰 화면 결정

두 요청을 병렬로 보내고 Promise.allSettled로 각각의 결과를 받습니다. 토큰 발급이 실패하면 입장을 중단합니다. 상태 조회만 거절되면 임시 CONNECTING 상태와 오류 안내를 표시하면서 접속을 시도합니다. 연결 중에는 3초 간격으로 상태를 다시 읽습니다.

오류와 영상 방을 동시에 검사

테스트에서 인플루언서의 토큰은 정상으로 두고 상태 요청에만 오류를 주입했습니다. LiveKit 컴포넌트를 대체하고 폴링을 꺼서, 영상 방과 오류 안내가 동시에 표시되는 분기를 확인했습니다.

입력과 화면으로 읽는 판정 기준

입력 조건화면의 처리확인 방법
토큰 정상 · 상태 조회 거절영상 방과 상태 오류 안내를 함께 표시오류 주입 회귀 테스트
토큰 발급 실패영상 방 입장 중단입장 분기 코드
상태 조회가 계속 대기두 요청의 결과가 확정될 때까지 대기별도 타임아웃 검증 필요

이 시험은 두 실물 단말에서 첫 영상·음성이 도달하는 시간이나 통화 성공률을 측정하지 않았습니다. 담당한 화면의 실패 복구를 검증한 결과입니다.
