어떤 프로젝트인가요?

팬과 인플루언서가 온라인으로 만나는 영상 팬미팅 서비스입니다. 통화 입장과 진행 상태를 다루는 프런트엔드를 중심으로 작업했습니다.

통화에 꼭 필요한 조건과 보조 상태 조회를 구분했습니다. 장치 선택 실패와 운영 화면의 상태 지연을 살펴보고, API 응답이 사용자 화면에 반영되는 흐름을 개선했습니다.

THE QUESTION

상태 조회 하나 때문에 통화까지 막혀야 할까요?

유효한 입장 토큰을 받아도 보조 상태 API가 실패하면 통화가 시작되지 않는 흐름이 있었습니다. 각각의 API가 실제로 어떤 역할을 하는지부터 다시 나눴습니다.

판단하고 바꾼 과정

01

사용자의 통화 목적부터 다시 보기

유효한 입장 토큰을 받아도 보조 상태 조회가 실패하면 영상 화면 전체가 막혔습니다. 통화에 꼭 필요한 인증과 타이머·종료 표시용 상태를 같은 성공 조건으로 다뤄야 하는지 다시 확인했습니다.

02

필수 정보와 보조 상태를 나누기

두 요청의 결과가 확정된 뒤 각각 판정하도록 보완했습니다. 토큰 실패는 입장을 중단하고, 상태 조회만 거절되면 영상 화면과 안내를 표시한 뒤 3초 간격으로 상태를 다시 확인하도록 했습니다.

03

이전 장치와 오래된 상태에 대응

저장된 카메라·마이크가 사라졌을 때 대체 장치를 허용하도록 조건을 조정했습니다. 운영 명령 뒤에도 30초 공개 캐시가 이전 상태를 보이던 문제는 운영 조회의 캐시 우회와 명령 응답 반영으로 보완했습니다.

통화 흐름과 운영 화면을 각각 복구할 수 있게

필수 / 보조

통화 입장 조건과 상태 조회의 책임 분리

3초

보조 상태를 확인하는 조회 간격

인증은 정상으로 두고 상태 조회에만 오류를 넣은 검사에서 영상 화면과 오류 안내가 함께 표시되는 결과를 확인했습니다. 관련 테스트 7개 통과 보고가 있으며, 실제 사용자 통화 성공률과 복구 시간은 별도 측정하지 않았습니다.

확인 범위

프런트엔드에서 통화 진입 조건, 장치 선택, 운영 상태 표시를 개선한 결과입니다. 실제 사용자 환경의 통화 성공률은 별도로 측정하지 않았습니다.

다음 작업에 가져갈 기준

한 기능이 실패했을 때 모든 흐름을 중단하기보다, 사용자가 계속할 수 있는 부분과 복구해야 하는 부분을 구분하는 것이 중요했습니다.
