필요한 데이터와 모을 수 있는 데이터 사이

API 한도와 시간대별 누락을 설명한 수집 담당자의 의견이 연산 계획을 바꿨다.

연산 담당자에게 필요해 보였던 정보

예측에 영향을 줄 것 같아 실시간 버스·지하철 위치, 인구 혼잡도, 지역별 날씨, 정류장 사이의 과거 소요시간을 폭넓게 요청했다. 하지만 수집 담당자는 API 요청 횟수에 한도가 있고, 자료마다 날짜와 시간대가 달라 모두 같은 기준으로 맞출 수 없다고 설명했다.

서로 맡은 일의 조건을 나누기

각 자료가 모델 학습과 실시간 소요시간 계산에 왜 필요한지 전달하고, 팀원이 판단한 수집 가능성과 누락 조건을 함께 확인했다. 필요한 항목을 계속 추가하기보다 수집 가능한 자료를 기준으로 학습 데이터를 조정했다. 실시간 계산에 영향을 주는 자료도 상의해 수집하고 적용했다.

정보의 존재와 활용 가능성

어떤 자료가 공개되어 있다는 것만으로 다른 자료와 연결하거나 예측 시점에 사용할 수 있는 것은 아니었다. 후속 모델 검토에서도 이 기준을 유지했다. 가용 시점이 확인되지 않은 날씨를 최종 버스 모델에서 제외한 이유도 같은 맥락이었다.

협업에서 가져갈 질문

필요한 작업을 설명하는 것과 상대가 실행할 수 있는 범위를 함께 정하는 것은 달랐다. 수집 담당자의 설명을 듣고 나서야 연산에 필요한 입력뿐 아니라 그 입력을 만들어 내는 과정까지 확인해야 한다는 것을 배웠다.
